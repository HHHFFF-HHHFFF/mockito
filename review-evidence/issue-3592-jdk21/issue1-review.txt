PROBLEM AND REPRODUCTION
The runtime-retained annotation in
mockito-core/src/test/java/org/mockitousage/annotation/custom/org/mockito/DoNotMock.java
has reason and value attributes. DoNotMockMessageTest.CustomType applies it with
reason="Use ConcreteFake instead" and value="custom-policy-3592".
Calling Mockito.mock(CustomType.class) on the baseline throws DoNotMockException,
but its message mentions only @org.mockito.DoNotMock, omitting both attributes.
The original exception and stack trace are preserved in 3592-message-before.txt
and the red-run XML. The corrected message is in 3592-message-after.txt.
The after-message sample directly calls the enforcer on the same test fixture;
the 28-test green run separately verifies the public Mockito.mock() path.

CALL PATH
1. Mockito.mock() delegates to MockitoCore.mock().
2. MockitoCore builds MockCreationSettings and calls checkDoNotMockAnnotation()
   before creating the mock. The static-mocking path performs the same check.
3. The configured DoNotMockEnforcer checks the requested class and extra interfaces.
   Its recursive helper checks the type itself, its superclass and interfaces,
   stopping at the first violation. Allowed types may be cached; rejected types
   return a message and are not added to that cache.
4. DefaultDoNotMockEnforcer.checkTypeForDoNotMockViolation(Class) checks runtime
   annotations using the existing fully qualified name suffix rule.
5. MockitoCore throws DoNotMockException with the returned message.
Only step 4 changes; hierarchy traversal and enforcement remain unchanged.

IMPLEMENTATION
For the official DoNotMock annotation, return the original message and reason.
Use the already retrieved annotation instance to read reason(), avoiding another
annotation lookup. The Class equality check preserves the existing type check.
For a custom matching annotation, concatenate the annotation instance itself.
Its toString() supplies the actual annotation name and attributes. Do not prepend
another @ because toString() already includes it. No reflective lookup of a
particular attribute is needed: custom annotations need not define reason().
No API, dependency, matching rule or mockability behaviour changes.

COMPATIBILITY AND EDGE CASES
The official default and explicit reason retain exactly the old message format.
Custom annotations without attributes still identify the annotation. Parent
classes, inherited interfaces and extra interfaces are checked as before.
Normal types and unrelated annotations remain mockable. Tests check meaningful
custom fields independently, without depending on reflection attribute order.
The existing first-matching-annotation behaviour is unchanged.
